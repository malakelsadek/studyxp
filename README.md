# Study XP

A gamified, pixel-art social study space. Move a character around a shared 2D room, run a synced study timer with the people around you, and keep each other accountable — all in the browser.

## Features

### Shared rooms
- Real-time 2D room rendered with Phaser, with everyone's character visible and moving live via Socket.IO
- Create your own room or join an existing one, protected by a password
- Per-room capacity limits, so a room only holds as many people as it's meant to
- Rename a room and upload a custom background image
- Live player count per room on the dashboard

### Study timer
- Pomodoro mode with configurable work/break durations and automatic phase switching
- Stopwatch mode for open-ended sessions
- Toggle between a **shared** timer (synced for everyone in the room) and a **personal** one
- Study sessions are logged and feed into your personal stats

### To-do lists
- Shared room to-do list, or a personal one just for you
- See everyone else's personal to-do progress at a glance (a live completion percentage per person), so you know what the room is working on

### Character customization
- Six pixel-art character presets to choose from
- Pick your look from the dashboard; it's saved to your profile and shown to everyone in the room

### Chat & shortcuts
- Lightweight in-room chat overlay
- Keyboard-driven UX: `Alt+C` to chat, `Alt+T` to toggle the timer, `Alt+D` for the to-do list, `Esc` to close chat
- In-app shortcuts reference panel

### Profiles & stats
- Editable display name, bio, and interests
- Activity heatmap of study time, plus overall study stats
- Guest login for trying the app without creating an account, or a full email/password account

## Tech stack

| | |
|---|---|
| **Client** | React 19, TypeScript, Vite, Phaser 3, Socket.IO client, React Router |

```
    room/           In-room UI: timer, to-do, chat, settings, side nav
    profile/        Profile modal, activity heatmap
    socket/         Socket.IO client + shared types
    lib/            API client

server/            Express + Socket.IO backend
  src/
    auth/           Register/login, JWT issuing, auth middleware
    rooms/          Room CRUD, password/capacity changes, background upload
    users/           Profile endpoints
    stats/           Study session logging
    socket/          Realtime room state (players, timer, chat, todos)
  prisma/           Database schema & migrations

assets/             Repo-level images (README preview, design references)
```

## Getting started

This is an npm workspaces monorepo (`client` + `server`).

```bash
npm install

# copy env files and fill in DATABASE_URL / JWT secret / etc.
cp client/.env.example client/.env
cp server/.env.example server/.env

npm run dev          # runs client + server together
# or individually:
npm run dev:client
npm run dev:server
```

## Deployment

The app deploys as three pieces, each connected to this GitHub repo so pushing to `main` redeploys automatically:

| Piece | Where | Notes |
|---|---|---|
| Postgres | [Neon](https://neon.tech) | Free tier, gives you a `DATABASE_URL` |
| Server (Express + Socket.IO) | [Render](https://render.com) | Needs a persistent process (not serverless) for WebSockets |
| Client (Vite + React) | [Vercel](https://vercel.com) | Static build |

### 1. Database — Neon
Create a project, copy the pooled connection string it gives you. That's your `DATABASE_URL`.

### 2. Server — Render
This repo includes [`render.yaml`](render.yaml) as a Blueprint, so Render can configure the service from the repo instead of manual dashboard setup:
1. Render dashboard → **New +** → **Blueprint** → connect this GitHub repo.
2. It reads `render.yaml` and creates a `studyxp-server` web service (free plan, rooted in `server/`).
3. Set the required env vars when prompted:
   - `DATABASE_URL` — from Neon
   - `CLIENT_ORIGIN` — your Vercel URL once you have it (e.g. `https://studyxp.vercel.app`); update this after step 3 if you set it up first
   - `JWT_SECRET` is auto-generated by the blueprint
4. Every push to `main` triggers `npm install && npx prisma generate && npm run build`, then `npx prisma migrate deploy && npm start` — so new Prisma migrations committed to `server/prisma/migrations` apply automatically on deploy.
5. Note the resulting URL, e.g. `https://studyxp-server.onrender.com`.

**Known limitation:** room background uploads (`multer` → `server/uploads`) are written to local disk. Render's free plan has an ephemeral filesystem, so uploaded images are lost on every redeploy/restart. To fix: either add a [Render persistent disk](https://render.com/docs/disks) (requires a paid instance type) mounted at `server/uploads`, or switch the upload handler to object storage (e.g. Cloudflare R2 or S3). Fine to defer until uploads are actually needed in production.

### 3. Client — Vercel
1. Vercel dashboard → **Add New** → **Project** → import this repo.
2. Set **Root Directory** to `client` (Vercel auto-detects the Vite framework preset from there).
3. Add env var `VITE_SERVER_URL` = your Render URL from step 2 (e.g. `https://studyxp-server.onrender.com`).
4. Deploy. Every push to `main` redeploys automatically.
5. Go back to Render and set `CLIENT_ORIGIN` to this Vercel URL (needed for CORS + Socket.IO to accept connections from it), which triggers a redeploy.

### Updating the live site
Once both are connected, `git push` to `main` is the entire deploy step — Render rebuilds/migrates the server, Vercel rebuilds the client. No manual redeploy needed.
